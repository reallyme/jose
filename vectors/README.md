# JOSE Conformance Vectors

[manifest.json](manifest.json) lists the fixture suites and expected case counts.
Requirement records associate specification sections with implementation files
and tests. `schema-operations.json` contains binary requests, ProtoJSON requests,
and expected V2 response bytes for operation-contract integrations.

Audit the fixtures from the repository root:

```sh
cargo run --locked --manifest-path tools/vector-audit/Cargo.toml --bin reallyme-jose-vector-audit -- .
```

For ECDH-ES, this tool verifies AES-GCM with the recorded derived CEK; it does
not independently recalculate key agreement or Concat-KDF. ES256 fixtures
include valid high-S signatures, which verifiers must accept.

## Regenerating the panva fixtures

`panva-jose.json` records the source library version. Its ES256/EdDSA JWS,
ES256 JWT, and P-256/A128GCM ECDH-ES cases are generated by
`tools/panva-goldens`:

```sh
npm --prefix tools/panva-goldens ci
npm --prefix tools/panva-goldens run generate
```

Generation changes ECDSA signatures and ephemeral JWE values. Review the
resulting fixture and manifest changes before keeping them. The suite excludes
ES256K because panva/WebCrypto does not provide secp256k1 JOSE signing support.
Fixture keys use deterministic low scalars and must never be used in production.
