# reallyme-jose-proto

`reallyme-jose-proto` contains the generated Buffa bindings for the versioned
ReallyMe JOSE protobuf boundary.

The crate is intentionally small: it publishes the checked-in generated message,
view, JSON, and protobuf encoding types used by `reallyme-jose` wire helpers.
Both supported `reallyme-jose` runtime lanes include these contract types. This crate does not run an
RPC service and does not own JOSE cryptographic behavior.

The schema exists to give FFI, WASM, mobile, generated-SDK, and process
boundaries one deterministic request/result representation without duplicating
JOSE policy or dispatch logic in every language. It defines messages only: no
protobuf `service`, network transport, endpoint, streaming, or discovery
contract is part of this crate.

## Boundary Contract

JOSE follows the ReallyMe
[Engineering Philosophy](https://github.com/reallyme/.github/blob/main/ENGINEERING_PHILOSOPHY.md)
and [Architecture Standards](https://github.com/reallyme/.github/blob/main/ARCHITECTURE.md).
This contract was reviewed against the
[pinned architecture revision](https://github.com/reallyme/.github/blob/a31da22424f205449a21306b6a1eddeefc5e1472/ARCHITECTURE.md).

The schema defines `JoseOperationRequest` as the single executable request and
`JoseOperationResponse` as the canonical versioned response. Generated oneofs
identify the selected operation and its `result` or `error` outcome without an
opaque nested payload.

The intended adapter flow is:

1. Encode one operation in the `JoseOperationRequest` `oneof`.
2. Call the embedding adapter's V1 operation execution function with those bytes.
3. Decode `JoseOperationResponse`, require contract version V2, require the
   operation variant to match the request, and handle its generated outcome.

Malformed input before operation selection uses `boundary_error`. Semantic,
provider, and backend failures after selection remain nested beneath the
selected operation. The JSON request representation is generated ProtoJSON;
canonical results remain binary protobuf and have identical meaning across the
binary and JSON request paths.

FFI, JNI, Swift, Kotlin, and Android adapters all use the versioned,
operation-discriminated response and never infer result types from opaque
payload bytes.

Rust owns JOSE validation, dispatch, and policy. Swift, TypeScript/WASM,
Kotlin/JNI, and Android use the generated request and response contract at their
shared boundaries and expose language-specific convenience APIs. Compact JWS,
JWT, and JWE retain their standard wire formats. The SDKs run the same
[conformance fixtures](../../vectors/README.md) through their native bridges.

Algorithm selectors use family-local numeric bands aligned with the
corresponding `reallyme-crypto-proto` families where the algorithms overlap:
EdDSA is in the 100 band, elliptic-curve suites in the 200 band, and AES-GCM
content encryption at 100/110/120. These are protobuf identifiers, not JOSE
registry values. The compact pre-release values are reserved so old request
bytes fail closed instead of being silently reinterpreted.

`JoseError` preserves the public error branch:

- `primitive` for caller input, malformed protobuf or JSON, JOSE primitive, or
  policy failures;
- `provider` for unsupported algorithms, unavailable providers, and randomness
  failures;
- `backend` for serialization, key-derivation, and internal implementation
  failures after a request has crossed the boundary.

Each SDK preserves the same operation branch and reason in its public error
type. SDK-local setup codes distinguish failures when the caller can diagnose
or recover differently. Swift's `nativeSymbolMissing` identifies a missing
library export. Provider failures with the same recovery use a general SDK
code. A setup distinction becomes a protobuf reason when it needs to cross a
shared boundary.

Several request and result fields carry private keys, direct CEKs, claims JSON,
plaintext, or correlating protocol metadata. Generated-SDK and host adapters
must treat those bytes as sensitive, avoid logging them, and zeroize owned
buffers after use.

The runtime and both local generators use the published ReallyMe Buffa `=0.1.2`
family. Rust dependency aliases remain `buffa`. Generated byte and string fields
use `SecretBytes` and `SecretString` to wipe their live data and spare
capacity. Both types use `secrecy` for ownership. Each required `Clone` owns
an independent allocation.
The native cleanup profile also clears numeric fields, optional presence,
oneof cases, nested messages, and guarded repeated storage.

`buf.gen.yaml` selects the whole JOSE package for cleanup, disables unknown-field
storage, rejects unknown JSON fields, and selects both field JSON policies
explicitly. Bounded field hooks reserve guarded storage before copying fragmented
input. The byte JSON policy uses guarded Base64 input/output scratch. Owned
messages and borrowed views support explicit ProtoJSON export under those
field policies. `Debug` redacts their contents, including nested operation
variants. Reflection, lazy-view generation and imported well-known types are
currently unused. New imported message families must satisfy cleanup before
entering this profile.

Admission must decode the complete tree with `DecodeOptions::reject_unknown_fields()`
and the application size/depth limits. Disabling unknown storage alone does not
reject wire fields. Validate unknown fields against the original wire bytes.
Raw JSON must pass the application's JSON admission checks. A null collection
is absent, and a repeated string rejects null elements. For in-place updates, use
`DecodeOptions::clear_on_merge_error()` so a failed merge wipes the entire
destination, including values present before the merge.

JOSE generates borrowed views for the entire package. The caller keeps their
input in a wipe-owning buffer for the lifetime of the view. For a view that
owns its wire storage, use `buffa::sensitive::GuardedOwnedView` with explicit
unknown-field rejection and resource limits. `from_owned` encodes directly
into the guarded allocation. `decode` copies the input into guarded storage
and leaves the original buffer with the caller. The guarded owner exposes a
borrowed view for explicit serialization. Parser scratch and copies in managed
runtimes still need their own ownership controls.

JWE decrypt requests include a presence-sensitive protected-header validation
policy. `kid` can be required, and exact `kid`, `typ`, `cty`, `apu`, and `apv`
values can be bound to the protocol context. Message wrappers preserve the
difference between an absent expectation and an explicitly expected empty
value.
The wire reason `JWE_HEADER_POLICY_MISMATCH` covers both `typ` and `cty`
mismatches; `kid`, `apu`, and `apv` retain their separate reason codes.

The schema defines public algorithm and suite identity, claims, policies, limits,
error reasons, and caller-scoped capability requests. Rust's borrowed interfaces
are adapters to these operations. `api::execute` accepts generated requests;
`api::execute_with_providers` also resolves nonzero handles in a caller-owned
provider context. No global key registry or private-key export is required.

V2 deliberately breaks the pre-1.0 contract. JWE optional headers preserve absent
and present-empty values. JWT signing uses `header_options`: an absent message
defaults to `typ: JWT`, a present message without `typ` omits it, and a present
empty `typ` is rejected. JWT verification selects exactly one `verification.mode`
(`signature_only`, `claims`, or `temporal_only`). The former root `typ`,
`temporal_policy`, `signature_only`, `expected_issuer`, and `expected_subject`
fields are retired and reserved. `JoseSignatureAlgorithm` is the single signature
identity for JWT, JWS, and raw-signature operations. Compact JWS accepts EdDSA
and ES256; JWT also accepts ES256K. Unsupported operation/algorithm combinations
fail closed. Native selectors, JOSE labels, SDK modes, and policy presets are
derived from schema metadata. Shared resource, length, compact-format, and
encoding failures replace redundant per-area reason codes, whose numbers and
names are also reserved. Unknown and retired request fields fail closed.

Regenerate consumers and rebuild native/WASM binaries and SDKs together. The
protobuf package remains `reallyme.jose.v1` and native function signatures retain
ABI V1; the response's separate V2 contract marker detects incompatible SDKs.
Earlier pre-1.0 wire semantics are intentionally unsupported.

CI runs `buf lint`, `buf breaking --against crates/proto/compatibility/v2.binpb`,
contract reachability checks, and generated-code freshness checks. The frozen
descriptor is the V2 compatibility checkpoint, replacing the earlier published
baseline for this deliberate break. Do not refresh it as part of routine
generation. A subsequent deliberate contract break requires its own version and
reviewed checkpoint; compatible additions must continue to pass against V2.

Generated code is checked in rather than produced by `build.rs`. Refresh it with
the repository-level `buf.gen.yaml`:

```sh
cargo install reallyme-protoc-gen-buffa --version '=0.1.2' --locked
cargo install reallyme-protoc-gen-buffa-packaging --version '=0.1.2' --locked
node scripts/generate-jose-proto.mjs
```

## Install

```toml
[dependencies]
reallyme-jose-proto = { version = "0.5.0", features = ["generated"] }
```
